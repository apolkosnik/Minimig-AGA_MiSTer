## Bug #1: Bus Adapter DTACK Handshaking

### Problem

The TG68K030_Bus_Adapter state machine transitioned directly from `LONG_UPPER` to `LONG_LOWER` state without waiting for the system bus `dtack` signal to deassert. This violates the 68000-family bus protocol.

**Location**: rtl/TG68K030_Bus_Adapter.v

**Impact**:
- Would cause bus timing violations on real hardware
- Potential for bus contention between consecutive transfers
- Data corruption or system hangs during 32-bit long word operations

### Root Cause

The original 4-state FSM design assumed immediate transition between the two 16-bit cycles of a long word transfer:

```verilog
// INCORRECT (original):
LONG_UPPER: begin
    if (sys_dtack == 1'b0) begin
        // Save upper 16 bits
        data_buffer <= sys_data_read;
        // Immediately start second cycle - BUG!
        sys_addr <= cpu_addr + 2;
        state <= LONG_LOWER;
    end
end
```

The 68000 bus protocol requires:
1. Address strobe (AS) must deassert
2. DTACK must deassert (return to high)
3. Bus must idle before next transfer begins
4. AS can then be reasserted for next transfer

### Fix

Added `LONG_WAIT` state to properly implement bus handshaking:

```verilog
// CORRECT (fixed):
localparam IDLE         = 3'b000;
localparam LONG_UPPER   = 3'b001;
localparam LONG_WAIT    = 3'b010;  // NEW STATE
localparam LONG_LOWER   = 3'b011;
localparam WAIT_READY   = 3'b100;

LONG_UPPER: begin
    if (sys_dtack == 1'b0) begin
        if (cpu_write == 1'b0) begin
            data_buffer <= sys_data_read;  // Save upper 16 bits
        end
        sys_as <= 1'b1;      // Deassert AS
        state <= LONG_WAIT;  // Go to wait state
    end
end

LONG_WAIT: begin
    // Wait for dtack to deassert before starting second transfer
    if (sys_dtack == 1'b1) begin
        sys_addr <= sys_addr + 32'd2;  // Increment address by 2
        sys_as <= 1'b0;                // Assert AS for second cycle
        state <= LONG_LOWER;
    end
end
```

**Changes**:
- State machine expanded from 4 states to 5 states
- Changed state register from `reg [1:0]` to `reg [2:0]`
- LONG_UPPER deasserts `sys_as` and transitions to LONG_WAIT
- LONG_WAIT waits for `sys_dtack == 1'b1` before proceeding
- LONG_LOWER starts only after proper bus idle

## Bug #2: Wire/Reg Type Mismatch in cpu_wrapper.v

### Problem

ATC invalidation arbiter signals were declared as `wire` but assigned in an `always @(*)` combinational block.

**Location**: rtl/cpu_wrapper.v (around line 668-670)

**Impact**:
- Quartus synthesis error: "Cannot assign to wire in procedural block"
- Build failure
- Project would not synthesize

### Root Cause

Verilog language rules:
- Signals assigned in `always` blocks must be declared as `reg`
- `wire` signals can only be assigned with continuous assignment (`assign`) or port connections

**Incorrect code**:
```verilog
// Signal declarations (lines ~668-670)
wire atc_inv_all, atc_inv_fc, atc_inv_fc_ea;
wire [2:0] atc_inv_fc_val;
wire [31:0] atc_inv_ea_val;

// Later in code (ATC invalidation arbiter)
always @(*) begin
    // Priority encoder for ATC invalidation
    if (pflush_inv_all) begin
        atc_inv_all = 1'b1;      // ERROR: Can't assign to wire!
        atc_inv_fc = 1'b0;
        // ...
    end
end
```

### Fix

Changed signal type from `wire` to `reg`:

```verilog
// CORRECT:
reg atc_inv_all, atc_inv_fc, atc_inv_fc_ea;
reg [2:0] atc_inv_fc_val;
reg [31:0] atc_inv_ea_val;
```

**Note**: In Verilog, `reg` does NOT necessarily mean a register (flip-flop). It simply means "a variable that can be assigned in a procedural block". Combinational logic assigned in `always @(*)` blocks uses `reg` type but synthesizes to combinational logic, not registers.

### Verification

- Syntax check: ✅ Pass
- Synthesis check: ✅ No errors
- Logic unchanged: ✅ Same functionality

## Bug #3: Missing Build System Entry

### Problem

The TG68K030_Bus_Adapter.v module was created but not added to the Quartus project file (files.qip), so it would not be compiled during synthesis.

**Location**: files.qip

**Impact**:
- Module would not be compiled
- "Undefined module" errors when trying to instantiate bus adapter
- Incomplete builds

### Fix

Added the module to files.qip:

```tcl
set_global_assignment -name VERILOG_FILE rtl/cpu_wrapper.v
set_global_assignment -name VERILOG_FILE rtl/TG68K030_Bus_Adapter.v  # ADDED
set_global_assignment -name VERILOG_FILE hps_ext.v
```

**Line added**: Line 24 in files.qip

### Verification

- File list check: ✅ Module now in compilation order
- Build completeness: ✅ All required files present

## Lessons Learned

### 1. Bus Protocol Compliance
**Issue**: Initial implementation didn't account for bus idle requirements
**Lesson**: Always review bus protocol timing diagrams, especially for split transfers
**Prevention**: Add protocol compliance checklist to design phase

### 2. Verilog Signal Types
**Issue**: Confusion between wire and reg types
**Lesson**: Signals in always blocks must be reg, regardless of whether they're combinational or sequential
**Prevention**: Use linting tools early in development

### 3. Build System Updates
**Issue**: New files not added to build system
**Lesson**: Every new file must be added to files.qip immediately
**Prevention**: Automated build file generation or verification script
